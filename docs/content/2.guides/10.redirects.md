When you move or delete a page, other sites and search results still link to the old URL.
Use `seo.redirects` to list each old URL in one place, with the date you added it.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  seo: {
    redirects: {
      '/blog/old-post': { to: '/blog/new-post', addedAt: '2026-10-13' },
      '/spring-sale': { statusCode: 410, addedAt: '2026-10-13', reason: 'The sale ended.' },
    },
  },
})
```

Learn when to redirect and when to return an error in the [HTTP Redirects](/learn-seo/nuxt/controlling-crawlers/redirects) guide.

## Moved URLs

An entry with `to` is a moved URL. A request for the old URL gets a permanent redirect.

- The default status is `301`. Set `statusCode: 308` to keep the request method, for example for a form `POST`.
- `to` is a path on your site, or an absolute URL on another site.
- The request query string is kept: `/blog/old-post?ref=mail` redirects to `/blog/new-post?ref=mail`.

Google treats 301 and 308 the same. Both tell Google that the new URL is the one to index.

Only redirect to a page with the same content.
If you redirect many deleted pages to the home page, Google can treat the redirects as soft 404 errors.
If no page replaces the old one, use a gone URL.

## Gone URLs

An entry with `statusCode` and no `to` is a gone URL. A request for the old URL gets your error page with that status.

- Use `410` when you deleted the content on purpose.
- Use `404` when you prefer the plain not found status.

Google drops 404 and 410 URLs from its index in the same way.
The 410 status records that you removed the page on purpose.

`reason` is a private note for you and your team. The module never sends it to visitors.

## Paths and Patterns

Write each key as a path without `app.baseURL`. The module adds the base URL to the redirect target.

A trailing `/**` matches the path and every path below it.
End `to` with `/**` to keep the rest of the path:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  seo: {
    redirects: {
      // /docs/v1/setup redirects to /docs/setup
      '/docs/v1/**': { to: '/docs/**', addedAt: '2026-10-13' },
      // every path below /legacy redirects to one page
      '/legacy/**': { to: '/archive', addedAt: '2026-10-13' },
    },
  },
})
```

- A trailing slash on a request does not change the match. `/blog/old-post/` matches `/blog/old-post`.
- An exact key wins over a `/**` key. A longer `/**` key wins over a shorter one.
- Keys cannot contain a query string, a hash, `:params`, or a `*` in the middle.

### i18n

With `@nuxtjs/i18n` and a prefix strategy, each entry also applies under every locale prefix.
With `prefix_except_default`, `/old` redirects to `/new`, and `/fr/old` redirects to `/fr/new`.

If a locale uses a translated path, add an entry for it. An entry that starts with a locale prefix applies only to that locale.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  seo: {
    redirects: {
      '/about-us': { to: '/about', addedAt: '2026-10-13' },
      '/fr/a-propos-de-nous': { to: '/fr/a-propos', addedAt: '2026-10-13' },
    },
  },
})
```

## Review Instead of Expiry

No entry expires on its own. A redirect keeps working until you delete it.

Google recommends that you keep redirects for at least one year, and for users, as long as possible.
After you remove a redirect, links to the old URL stop passing value to the new URL.

The module schedules a review instead.
When an entry is older than `redirectReviewAfterDays` (365 by default), `nuxt dev` and `nuxt build` list it:

```bash
[nuxt-seo-utils] WARN  1 `seo.redirects` entry is due for review (older than 365 days):
  - `/blog/old-post` → /blog/new-post (since 2025-10-13, 365 days)
  If an old URL still gets visits or backlinks, keep it and set `reviewedAt` to today.
  If it gets none, you can delete the entry.
```

To review an entry, check its traffic in your server logs or analytics, and its links in Google Search Console.

- If the old URL still gets visits or backlinks, keep the entry and set `reviewedAt` to today. The next review is one window later.
- If the old URL gets no visits and no links, you can delete the entry.

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  seo: {
    redirects: {
      '/blog/old-post': { to: '/blog/new-post', addedAt: '2025-10-13', reviewedAt: '2026-10-13' },
    },
  },
})
```

Set `redirectReviewAfterDays` to change the window, or to `false` to turn off the review.

### Browser Caching

Browsers can cache a permanent redirect with no end date.
So that a later change reaches returning visitors, each redirect sends `Cache-Control: public, max-age=3600`.
A `headers` route rule for the same path keeps its own `Cache-Control`.

## Redirect Chains

Each hop in a chain adds a request. Google follows up to 10 hops, and recommends a direct redirect to the final URL.

The module flattens chains in your entries. With `/a` to `/b` and `/b` to `/c`, a request for `/a` goes to `/c` in one hop.
The build lists each chain that it flattened.

- If entries form a loop, such as `/a` to `/b` and `/b` to `/a`, the build stops with an error.
- If a moved URL redirects to a gone URL, the build warns. Pick a live target, or make the old URL a gone URL.
- If an entry is not valid, the build stops with an error. The module never drops an entry without a message.

## Long Lists

For a long list, keep the entries in their own file and import it in your Nuxt config.
The `Redirects` type keeps the file typed.

```ts [redirects.ts]
import type { Redirects } from 'nuxt-seo-utils'

export default {
  '/blog/old-post': { to: '/blog/new-post', addedAt: '2026-10-13' },
  '/spring-sale': { statusCode: 410, addedAt: '2026-10-13' },
} satisfies Redirects
```

```ts [nuxt.config.ts]
import redirects from './redirects'

export default defineNuxtConfig({
  seo: { redirects },
})
```

A change to the file restarts the dev server, the same as a change to the Nuxt config.

## Static Hosting

A server answers each request with the status code. A static host has no server.

When you run `nuxt generate`, each exact moved URL becomes an HTML page with an instant meta refresh to the target.
Google treats an instant meta refresh as a permanent redirect.

A static build cannot send a 410 status or match a `/**` key. The build lists these entries.
For them, add redirect rules in your host configuration, or the host returns its 404 page.

## Client-Side Navigation

The redirects run on the server.
When a `NuxtLink` points to an old URL that no page matches, Nuxt loads the URL from the server, and the redirect applies.
When a catch-all page such as `[...slug].vue` matches the old URL, the app renders that page and skips the redirect.
Update your links to point at the new URL. [Nuxt Link Checker](/docs/link-checker/getting-started/introduction) flags links to a 301 redirect.

## Other Modules

- With [Nuxt Sitemap](/docs/sitemap/getting-started/introduction), the module adds `sitemap: false` to each old URL, so the sitemap does not list it.
- On a server build, the module adds `prerender: false` to each old URL. A crawled link to an old URL then cannot write an HTML file that hides the redirect.

## Route Rules

Nuxt `routeRules` also support `redirect`. Use the one that fits the job:

- Use `seo.redirects` for old URLs that you moved or deleted. It adds dates, reviews, chain checks, and 410 support. It also adds `app.baseURL` to each target.
- Use `routeRules` `redirect` for a temporary redirect, such as a `302` during maintenance.

## Verifying

Request the old URL and read the status and `location` header:

```bash
curl -sI https://example.com/blog/old-post | grep -iE '^(http|location)'
```
